Project context

What we set out to do

  • Give Agentforce access to internal knowledge (SKU, discount, SLA, competitive).
  • Route through Agent Fabric so the capability is registered and governable.
  • Prefer a Cursor-built agent for intelligent, cited answers.

What we learned

  • Cursor-managed hosting (v2) has no public MCP/A2A URL Fabric can register.
  • Hosted custom channels return empty 202s — A2A cards can’t be served sync.
  • A Mule MCP app can register today at https://<host>/mcp.

The decision in one sentence

Should Agentforce call Cursor capability as tools through a Mule MCP server, or as a peer agent with its own model reasoning?

Tools path

Agentforce (or Fabric broker) owns planning. Cursor/Mule surface returns evidence via MCP tools.

Agent path

Cursor agent owns the turn: search → reason → cite. Fabric reaches it over MCP ask or A2A message/send.

Will MCP be as “intelligent” as the agent?

MCP gives tools. An agent adds reasoning. Same evidence can look “smart” or “dumb” depending on who plans the calls.

Option A answer quality

Depends on Agentforce topic instructions + tool allowlisting. Strong if the topic forces search → get_document → cite.

Option B answer quality

Cursor instructions + cite skill + evals drive consistency. Better for multi-step retrieval and refusal when knowledge is missing.

Practical takeaway

If Agentforce prompt discipline is solid, Option A is enough. If you need BDK-grade behavior, choose Option B and self-host.
